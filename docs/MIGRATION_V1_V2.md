# v1/CME에서 v2로 단계별 이관

이 문서는 v1 출력 전체를 즉시 다시 받지 않고, 필요한 스페이스부터 v2로 옮기는 공식 수동 경로입니다. **자동 lockfile 변환이나 체크섬 재사용 기능은 아닙니다.** 이전 출력은 보관하고, 선택한 스페이스만 별도 v2 폴더에 한 번 내려받습니다. 아직 옮기지 않은 스페이스는 과거 시점의 v1 보관본이며, 최신 v2 결과가 아닙니다.

## 왜 lockfile을 복사하지 않나요?

- v1/CME는 `confluence-lock.json`, v2는 `confluence-export.lock.json`을 사용합니다. v2의 `schema_version`은2입니다.
- 변환 엔진·Markdown 옵션·경로 규칙이 달라 v1의 같은 페이지/체크섬이 v2의 같은 산출물을 뜻하지 않습니다. 파일명을 바꾸거나 `schema_version`만2로 고치면 안 됩니다.
- 현재 v2의 페이지 스킵 조건은 `skip_unchanged`가 켜져 있고, 저장된 페이지 버전·상대 경로가 같고, 대상 파일이 존재하는 것입니다. 저장된 `hash`를 매번 대조하는 방식이 아닙니다. 내용이 손상되었거나 수동 수정된 파일은 버전이 같아도 자동 복구되지 않을 수 있습니다.
- API에서 현재 페이지·첨부 메타데이터를 조회하는 과정은 스킵과 별개입니다. 두 번째 실행도 네트워크 요청이0이 되지는 않습니다.

## 1. 실행을 멈추고 되돌릴 지점을 남깁니다

1. v1과 v2의 예약을 끄고 실행 중인 내보내기가 끝났는지 확인합니다. 같은 폴더에 두 앱을 동시에 실행하지 않습니다.
2. v1 대상 폴더 **전체**를 다른 위치에 복사합니다. Markdown·첨부·lockfile·작업 설정을 포함합니다. 복사본의 몇 개 문서/이미지가 실제로 열리는지 확인합니다. 백업 전 원본을 이동·삭제하지 않습니다.
3. v2 `v1 설정 가져오기`는 작업/설정/지원되는 토큰 이관입니다. 출력물·lockfile을 v2 호환으로 바꿔주지 않습니다. 가져온 작업도 대상 폴더·범위·예약·정리 옵션을 다시 확인합니다.
4. 토큰은 앱의 연결 화면/OS 키체인으로만 관리합니다. lockfile·설정·로그를 공개 이슈에 그대로 올리지 않습니다.

## 2. 옮길 스페이스를 고릅니다

Confluence의 변경 내역과 담당자 확인으로 최근 변경되었거나 지금 필요한 스페이스 목록을 직접 만듭니다. 앱이나 아래 사전 점검은 v1 대비 변경된 스페이스를 자동 탐지하지 않습니다. 전체 최신본이 필요한 경우에는 모든 스페이스를 순차 이관해야 하며, 그때는 전체 다운로드 비용을 피할 수 없습니다.

| 스페이스 | 마지막 v1 보관 시점 | 지금 이관할 이유 | 새 v2 대상 | 검증 상태 |
| --- | --- | --- | --- | --- |
| 예시 DOCS | 사용자가 확인한 시점 | 최근 변경 | 별도 빈 폴더 | 미실행 |

실제 스페이스 키·내부 URL은 이 문서나 공개 댓글에 쓰지 말고 사내 기록에만 남깁니다.

## 3. 로컬 사전 점검 (선택)

저장소의 Python3 표준 라이브러리 스크립트는 파일을 쓰지 않고 두 lockfile의 유무/JSON 형태와 대상 분리를 확인합니다. Confluence에 접속하지 않고 작업 설정이나 토큰을 읽지 않습니다. Python은 이 선택적 점검에만 필요하며 v2 앱의 실행 의존성이 아닙니다.

```sh
python scripts/migration_preflight.py --legacy-dir /path/to/legacy-output --v2-target /path/to/fresh-v2-DOCS
```

Windows 예시:

```powershell
py scripts/migration_preflight.py --legacy-dir 'D:\Exports\legacy' --v2-target 'D:\Exports\v2-DOCS'
```

- 종료0: 안내서에 따라 **수동** 이관을 준비할 수 있습니다. 백업·권한·공간·실제 설정을 보장하지 않습니다.
- 종료1: 읽을 수 없거나 모르는 lockfile 형태가 있습니다. 원본을 보존하고 로컬에서 확인합니다.
- 종료2: 경로나 대상 분리가 올바르지 않습니다. v1 폴더의 하위/상위/동일 경로와 비어 있지 않은 v2 대상은 거부합니다.
- 8MiB가 넘는 lockfile은 점검을 거부합니다. 큰 위키에서는 원본을 올리지 말고 로컬에서 별도 검토합니다. 스크립트는 lockfile의 페이지 내용·토큰·경로를 출력하지 않습니다.
- 이 점검은 폴더를 만들거나 백업/lockfile 변환/내보내기를 실행하지 않습니다. 일반적인 경로 실수를 줄이는 보조 수단이며, 점검 뒤 경로를 바꾸거나 링크를 교체하는 공격을 격리하는 도구가 아닙니다.

## 4. 스페이스 하나를 별도 작업으로 만듭니다

1. 연결을 확인한 뒤 `작업` → `새 작업`을 만듭니다. 원래 v1 작업을 덮어쓰지 않습니다.
2. 대상은 v1·백업과 겹치지 않는 **새 빈 v2 폴더**로 정합니다. 스페이스마다 작업과 대상 폴더를 분리합니다. 하나의 lockfile을 여러 부분 범위가 번갈아 공유하지 않게 합니다.
3. 범위는 `spaces`를 명시하고 이관할 스페이스 URL **하나만** 입력합니다. `auto`나 사이트 전체 `orgs`를 선택하지 않습니다. 예시 형식은 `https://YOUR-SITE.atlassian.net/wiki/spaces/SPACEKEY`이며 실제 주소는 본인 환경을 사용합니다.
4. `변경 없는 페이지 건너뛰기` (`skip_unchanged`)는 켜고, `사라진 파일 정리` (`cleanup_stale`)는 **끕니다**. 예약도 끕니다. 기본값은 정리가 켜져 있으므로 그대로 실행하지 않습니다.
5. 링크/경로/첨부/본문 옵션을 기록합니다. 이후 옵션을 바꾼다면 페이지 버전이 같아도 새 출력이 필요할 수 있으므로 별도 폴더에서 다시 검증하거나 스킵을 끕니다.
6. 한 번 실행하고 로그의 실패·취소·누락을 확인합니다. 선택한 스페이스는 처음 한 번 다시 받으므로 시간·API 트래픽·첨부 다운로드 비용이 생깁니다. 다른 스페이스는 이 작업으로 갱신되지 않습니다.

> `cleanup_stale`은 범위 안에 이번에 보이지 않은 lock 항목을 지울 수 있습니다. 전체 사이트용 lockfile을 한 스페이스 작업으로 재사용하면 다른 스페이스 결과가 정리될 위험이 있습니다. 이 안내서는 빈 별도 대상·정리 끄기·스페이스별 분리를 사용합니다.

## 5. 비교하고 다음 범위를 결정합니다

- 스페이스별 페이지 수·첨부 수·실패 수를 확인합니다. 대표 문서의 표/코드/매크로/한국어·첨부·상대 링크를 직접 열어봅니다. v1과 v2의 Markdown이 byte 단위로 같다고 기대하지 않습니다.
- 새 폴더에 `confluence-export.lock.json`과 schema2가 생겼는지 확인합니다. v1 lockfile은 원래 위치에 남겨둡니다.
- 옵션을 바꾸지 않고 같은 작업을 한 번 더 실행해 정상 스킵되는지 확인합니다. 버전·경로가 바뀌거나 파일이 없으면 다시 처리됩니다. 첨부는 별도 버전 조건으로 확인됩니다.
- 실패했다면 새 v2 대상과 실행 기록을 보존해 조사합니다. v1 보관본으로 돌아갈 수 있고, 불완전한 v2를 최신본으로 표시하지 않습니다. 이 안내서는 자동 롤백이나 자동 병합을 하지 않습니다.
- 검증된 스페이스만 v2 사용으로 전환하고 나머지는 v1 보관본이라는 표시를 유지합니다. 나머지는 필요할 때 반복합니다. 원본/백업 삭제와 정리 옵션 재활성화는 별도 판단입니다.

## 검증 근거와 한계

기준 소스: `src-tauri/src/exporter/lockfile.rs`, `src-tauri/src/exporter/mod.rs`, `src-tauri/src/models.rs`, `ui/src/screens/JobEditor.tsx`. 사전 점검의 임시 폴더 회귀 테스트는 `python -m unittest discover -s tests -p 'test_migration_preflight.py'`로 실행합니다. 실제 Confluence 접속이나 대형 위키의 비용 절감률은 검증하지 않았습니다. 증분 체크섬 자동 변환은 후속 과제이며 이 문서는 이를 구현했다고 주장하지 않습니다.
